## 0. Зафиксированный стек


| Слой                                        | Выбор                                                             | Зачем                                                                      |
| ------------------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Клиент                                      | Expo / React Native + TypeScript (`ReactNative-version/frontend`) | один код, привычный стек                                                   |
| Локально на устройстве                      | **SQLite**                                                        | работает без интернета                                                     |
| Облако / источник правды между устройствами | **PostgreSQL на Neon**                                            | бесплатный tier не усыпляет так, как типичный free Supabase; уже есть опыт |
| API                                         | **NestJS** (`ReactNative-version/backend`)                        | auth, CRUD, sync, Groq-прокси, позже MCP                                   |
| Auth                                        | свой (Nest + JWT или sessions) поверх Postgres                    | **без Supabase**                                                           |
| AI в приложении                             | лёгкий ассистент → Nest → **Groq** (ключ только на сервере)       | шаблоны, если нет сети / 429                                               |
| AI за компом                                | MCP → тот же Nest API                                             | Cursor правит расписание                                                   |
| Flutter `flutter-version/`                  | архив / референс UI и формул                                      | не развиваем параллельно                                                   |


**Не делаем:** MongoDB в этом проекте, IAP, серверный push в первой рабочей версии, live-merge двух устройств с ручным слиянием.

### SQLite и Postgres — не «или», а два этажа

```
Телефон / Web (офлайн)
  SQLite  ← UI всегда читает отсюда
     │
     │  есть сеть: push/pull изменений
     ▼
  NestJS
     ▼
  Neon PostgreSQL  ← облачная правда, бэкап, Web с другого ПК, MCP
```

Синхронизация **возможна и так и задумана**. Схема таблиц на клиенте и сервере максимально одинаковая (`id`, `updated_at`, `deleted_at`). Конфликты в v1: **last-write-wins** по `updated_at` (один основной пользователь — ты). Два устройства одновременно без UI merge — не цель первой версии.

Web за компом с интернетом может ходить в API, но **кэш SQLite всё равно** нужен, если обещаем офлайн.

## 1. Принцип слоёв (как идём)

Не пилим XP, пока нельзя сохранить и открыть график без сети.

1. **Каркас** — слои кода, пустые экраны, память. *(частично уже в* `ReactNative-version/frontend/`*)*
2. **Рабочее ядро** — расписание + сегодня + правка + локальная SQLite.
3. **Облако** — Nest + Neon + логин + sync.
4. **Ассистент** — шаблоны + Groq через API.
5. **Продукт поверх ядра** — цели недели, закрытие дня, отчёты (без магазина).
6. **Геймификация** — XP, огонёк, профиль *(магазин и косметика — после ассетов, см. §7)*.
7. **MCP + полировка** — Cursor-tools, уведомления, uk *(экран Shop — заглушка до ассетов)*.

Каждый слой заканчивается **рабочей проверкой**, не «файлы появились».

## 1.1 Как возвращать UI (Flutter → Stitch → RN)

Референс вида: тёмный фон, лаванда, онбординг (Welcome / сферы), Today, Week, стекло-карточки, FAB ассистента. Сейчас это Flutter (`flutter-version/`) и скрины. Новые макеты делаем в **Stitch** (с кодом), в RN **не копируем HTML/React из Stitch целиком**.

### Что брать из Stitch


| Брать                                    | Не брать в RN как есть                       |
| ---------------------------------------- | -------------------------------------------- |
| Цвета, радиусы, отступы, типографика     | сырой HTML / CSS / `div`                     |
| Структура экрана (шапка, список, таббар) | веб-`backdrop-filter` без проверки на native |
| Состояния кнопок, сетка сфер             | отдельный роутинг Stitch                     |


Вынести в `ReactNative-version/frontend/src/ui/theme.ts` (или рядом): background, surface, accent (lavender), text, radius. Экраны импортируют тему, не hex из макета в каждом файле.

Строки в макетах могут быть **uk** — в приложении первой рабочей версии **EN**, uk в фазе 6. Макет = картинка; `l10n` = ключи.

### Когда какой кусок UI


| Когда                                 | Что возвращаем                                                                                             | Готово когда                                                            |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| **Фаза 1** (сейчас, параллельно ядру) | Только **токены**: тёмная тема, акцент, таббар не бежевый. Списки Today/Routine рабочие, без nebula и blur | Эмулятор/телефон: тёмный экран, читаемый текст, те же данные SQLite     |
| **Конец фазы 1**                      | Каркас онбординга: 2–3 шага, Skip / Back / Next, без идеальной картинки                                    | Можно пропустить и попасть в Today                                      |
| **Фаза 4**                            | Today и Week «как в макете»: дата, чекбоксы, цели, полоска дней, модалка цели                              | Фичи фазы 4 работают **и** выглядят близко к Stitch                     |
| **Фаза 3**                            | Пузырь / кнопка ассистента по макету; чат простой                                                          | Не блокирует sync                                                       |
| **Фаза 5**                            | Профиль: XP, уровень, огонёк, предупреждения. Shop — только **«Store soon»** (без каталога)                | После фазы 4                                                            |
| **Фаза 5b** *(позже)*                 | Магазин за XP, экипировка, слои ассистента — когда будут ассеты / Stitch                                   | Не блокер фазы 5                                                        |
| **Фаза 6**                            | MCP, напоминания, nebula/glass на Today                                                                    | Не блокер ядра                                                          |
| **Сейчас (после 5)**                  | **Полировка уже живущих экранов:** кнопки, таббар, модалки, анимации, отступы, состояния press             | Приложение приятно пользоваться каждый день; 5b магазин **не** начинать |


Flutter не портируем виджет за виджетом. Stitch — актуальный макет; Flutter — запасной референс, если Stitch ещё пустой.

### Правило

Сначала экран **делает работу** (сохранил пункт, отметил день), потом подтягиваем вёрстку из Stitch на **этот** экран. Не ждать полный набор макетов, чтобы начать SQLite. **Магазин и косметику** из Stitch не пилим, пока нет ассетов — см. §7 и **фазу 5b**.

## 5. Фаза 3 — Ассистент (лайтовый)

- [x] Локальные шаблоны (уже идея Flutter `assistant_picker`) — всегда
- [x] `POST /assistant/chat` на Nest: контекст = сегодняшние пункты, не вся БД
- [x] Groq key только в env сервера; rate limit на user
- [x] UI: bubble / короткий чат; 429 или нет сети → шаблон, не пустой краш
- [x] История чата не обязательна в облаке

**Готово когда:** с телефона с сетью задаёшь «что у меня сегодня» и получаешь ответ по **реальным** пунктам SQLite/Postgres; без сети — живая заготовка.

**Любой день (не только today):** бэкенд уже принимает `dayKey`. В фазе 3 клиент всегда шлёт календарное сегодня. Расширение — **после фазы 4 или вместе с MCP (фаза 6)**, не блокер ядра недели:

- UI: день с экрана Today (стрелки) **или** выбор даты в чате.
- Тот же `POST /assistant/chat` с другим `dayKey` — вчера / завтра / любой день шаблона.
- MCP: не только `get_today`, а `get_day(date)` и `get_week_schedule` — спрашивать прошлое и будущее из Cursor.

Не грузить в Groq всю историю сразу: один день или одна неделя в контексте, как сейчас.
