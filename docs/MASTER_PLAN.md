Документ зафиксирован как **опорная спецификация** для разработки. Цифры и формулы — **стартовые**, их нормально менять после тестов.

## 1. Продукт: одна фраза и ценность

**Что это:** планер недели с **рутиной по дням**, **целями по сферам жизни**, **дневными и недельными отчётами**, мягкой **геймификацией** (XP, огонёк за сбалансированные дни), **магазином косметики** и **настраиваемым ассистентом** (круглый emoji-стиль).

**Для кого:** людям, которым не хватает структуры, но не нравятся «только работа» и токсичные стрики.

**Не конкурируем с:** полноценным календарём компании, трекером рабочего времени для биллинга, терапией.

## 2. Сферы жизни (рекомендованный набор)

Набор **фиксированный в v1** (6 сфер) — так проще баланс, отчёты и огонёк. Названия в UI можно сделать дружелюбными.

| ID | Сфера | Примеры целей / рутины |
|----|--------|-------------------------|
| `work` | Работа / учёба | дедлайны, фокус-сессии, пары, проекты |
| `body` | Тело / здоровье | сон, шаги, спорт, врач, вода |
| `social` | Люди | созвоны, встречи, сообщения близким |
| `rest` | Отдых / удовольствие | хобби, серии, игра, «ничегонеделание» без вины |
| `home` | Быт / дом | уборка, финансы дома, мелкий ремонт |
| `growth` | Развитие | книги, курс, язык, нерабочее обучение |

**Почему не 10+ сфер:** перегруз при вводе и в отчётах; баланс огонька сложнее объяснить.

**Опционально позже:** подписи пользователя к сфере (не новые сферы) или «теги» внутри сферы.

## 3. Ключевые сущности (модель данных, логическая)

Ниже — **концептуально**; реализация в SQLite / Drift / Realm и т.д. — на этапе выбора стека.

### 3.1 Пользователь / профиль
- `userId` (идентификатор из облачного аккаунта, например Supabase/Firebase `uid`; локальный кэш на устройстве)
- отображаемое имя, аватар (опционально)
- текущий **XP**, **уровень** (косметический), экипировка ассистента (ссылки на id предметов)
- купленные предметы магазина
- настройки: язык, частота сообщений ассистента, «тихий режим», лимиты напоминаний

### 3.2 Рутина (шаблон недели)
- `RoutineTemplate`: список `RoutineItem`
- `RoutineItem`: `id`, `title`, `sphere`, `weekdays` (битмаска 1–7), `order`, `effort` (`light|medium|heavy`), `isOptional`, `defaultTime` (опционально), `createdAt`

### 3.3 День (экземпляр)
- `DayKey`: дата в локальном календаре
- `DayState`: для каждого `RoutineItem` на этот день — `pending | done | skipped | moved`
- связь «задача дня → цель недели» опциональна (`goalId?`)

### 3.4 Цели недели
- `WeekKey`: год + номер недели (ISO) или понедельник как якорь
- `WeeklyGoal`: `id`, `weekKey`, `sphere`, `title`, `successCriteria` (короткий текст или чеклист), `targetCount` (например 3 тренировки), `progressCount`, статус `active | completed | failed | dropped`

### 3.5 Бонус-задачи
- `BonusTask`: `id`, `title`, `sphere?`, `xpReward`, `expiresAt?`, `claimed` (выполнена и начислено)
- **кап** начислений с бонусов — в правилах экономики (раздел 7)

### 3.6 Дневной отчёт
- `DailyReport`: `dayKey`, `mood?` (1–5 или эмодзи), `noteShort`, `noteReflection` (1–2 поля), `closedAt`
- вычисляемые поля при закрытии: `balanceScore`, `dayTier` (`green | yellow | red`), флаги перекоса

### 3.7 Недельный отчёт
- `WeeklyReport`: `weekKey`, агрегаты по сферам, выполнение целей, текстовые ответы пользователя (опционально), `generatedAt`

### 3.8 Огонёк (streak)
- `currentStreak`, `bestStreak`
- `warningsInWindow` (счётчик предупреждений в текущем окне)
- `lastGreenDay` (дата последнего «зелёного» дня)
- настройки окна предупреждений (см. раздел 8)
- **freeze tokens** (если вводим «спасательный день») — счётчик и cooldown

### 3.9 Магазин
- `ShopItem`: `id`, `type` (`profile_bg | name_style | avatar_frame | assistant_layer | assistant_voice_pack`), `slot`, `priceXp`, `assetRef`, `rarity?`, `isDefault`
- покупка: запись в `owned_items`

### 3.10 Ассистент
- слоты: `face`, `glasses`, `hair_hat`, `outfit`, `hand_item`, `extras`
- `voice_pack_id` — набор коротких фраз (локальные строки), не LLM в v1

### 3.11 События для аналитики (локально или в будущем в облако)
- `event`: тип, timestamp, payload (без PII в payload по возможности)

## 4. Пользовательские потоки (journeys)

### 4.1 Онбординг (первый запуск)
1. Приветствие + 1 экран «философии» (баланс важнее списка из 100 задач).
2. Выбор 6 сфер — можно **пропустить** и оставить дефолт.
3. Мастер: **3–5 пунктов рутины** на неделю (шаблон).
4. Мастер: **1–2 цели на текущую неделю** (разные сферы поощряются подсказкой).
5. Имя + минимальная настройка ассистента (бесплатные дефолты).
6. Показать, где «сегодня», где «отчёт вечером», где огонёк.

### 4.2 Типичный день
1. Экран **Сегодня**: список рутины на день + прогресс целей недели (компактно).
2. Отметки выполнения / пропуск / перенос на завтра (ограниченно, чтобы не злоупотребляли).
3. Вечером (или по кнопке): **закрыть день** → короткий отчёт → расчёт дня → XP → сообщение ассистента → обновление огонька.

### 4.3 Неделя
1. Экран **Неделя**: цели + календарь «как прошли дни» (цветовые метки green/yellow/red).
2. Понедельник или вручную: **планирование недели** — редактирование целей, лёгкая правка рутины.

### 4.4 Магазин и профиль
1. Профиль: XP, уровень, огонёк, рекорд, экипировка.
2. Магазин: фильтр по типу, превью на ассистенте в реальном времени.

## 6. Логика «качества дня» и отчёта (зелёный / жёлтый / красный)

Цель: **сбалансированное закрытие**, а не «максимум галочек».

### 6.1 Входные метрики (пример v0)
- **R** — доля выполненной рутины среди **обязательных** (не optional) на этот день: `done / (done + pending + skipped treated)` — уточнить в реализации; проще: `done / planned_required`.
- **S** — число **уникальных сфер**, в которых был хотя бы один `done` сегодня (по рутине и/или бонусам, связанным со сферой).
- **W** — перекос в сторону работы: если `work_done >= 3` и `rest_done + social_done == 0` и в неделе есть активные цели в `rest` или `social` → флаг `work_imbalance`.
- **E** — отчёт заполнен минимально: оба коротких поля не пустые **или** один блок + оценка настроения.

### 6.2 Классификация дня (стартовая)
- **Зелёный:** `R >= 0.5` **и** `S >= 2` **и** не `work_imbalance` **и** `E` выполнено.  
- **Жёлтый:** не зелёный, но `R >= 0.35` **или** (`S >= 2` и нет жёсткого перекоса).  
- **Красный:** всё остальное (очень мало сделано, сильный перекос, пустой отчёт при требовании E).

Пороги `0.5 / 0.35` — **подкрутка** после тестов.

### 6.3 Огонёк
- **+1 день к серии** только при **зелёном** дне (или при **жёлтом** с «мягкой политикой» — решение: в v1 только **зелёный** удлиняет серию, жёлтый даёт предупреждение без роста; см. раздел 8).

Рекомендация для простоты v1: **растёт только зелёный**; жёлтый не ростёт и не ломает сразу; красный тянет предупреждение.

## 7. Экономика XP (стартовые числа)

Все значения — **константы в одном конфиге** (`economy_config.dart` / json).

| Событие | XP (старт) |
|---------|------------|
| Обязательный пункт рутины `light` | 5 |
| `medium` | 8 |
| `heavy` | 12 |
| Optional пункт | 50% от базы |
| Цель недели завершена | 80 |
| Частичная цель (например 2/3) | 30 |
| Качественный дневной отчёт (E + зелёный день) | 25 |
| Жёлтый день, но отчёт заполнен | 10 |
| Бонус-задача (базово) | 15–40 по сложности |
| Веха серии огонька (7, 14, 30 дней) | 50 / 100 / 200 |

**Капы (анти-фарм):**
- Суммарно с **бонус-задач** не более **120 XP в день**.
- Суммарно за **чисто рутину** не более **200 XP в день** (опционально).

**Уровни:** чисто косметика, например `level = floor(sqrt(totalXp / 100))` или таблица уровней; на уровни вешать титулы, не влияние на магазин цен — цены только в XP.

## 8. Огонёк и предупреждения (детально)

### 8.1 Поведение
- **Рост:** +1 к `currentStreak` за каждый **подряд** календарный день с **зелёным** итогом.  
  - Если пользователь **не открыл приложение** — трактовка: **нейтральный день не ломает** серию только если включён режим «выходной без телефона» (опционально, фаза 2). В **v1** проще: **нет закрытия дня = красный/жёлтый по умолчанию** или «день не завершён» без изменения серии до первого закрытия — это спорно.  
  - **Рекомендация v1:** серия считается по **датам, где день явно закрыт**. Пропуск закрытия **не увеличивает** серию и **не даёт предупреждение**, но **разрывает** серию через **48 часов без закрытия** (настраиваемо). Так меньше токсичности, чем «каждый календарный день».

Уточнённая политика v1 (предлагаю зафиксировать):
- **Серия увеличивается**, если в день D выполнено закрытие дня и итог **зелёный**.
- Если закрытие не сделано: **серия не меняется** до **дедлайна закрытия** (например до 04:00 следующего дня локально), после — **сброс серии** **без** предупреждений (просто «пауза жизни») ИЛИ **−1 к grace**. Проще для MVP: **нет закрытия до endOfNextDay → серия сбрасывается**, без цепочки предупреждений — и отдельно **предупреждения только для «плохого баланса»**.

Два независимых трека (чище для пользователя):
1. **Серия баланса** (огонёк): растёт на зелёных закрытиях подряд (по дням, когда закрыли).  
2. **Предупреждения баланса**: только если закрытие **есть**, но день **красный** или **жёлтый с перекосом**.

### 8.2 Предупреждения до сброса огонька
- Накопление `warnCount` за скользящее окно **7 дней**.
- Правила: **красный** день → +1 warning; **жёлтый + work_imbalance** → +1; **жёлтый без перекоса** → +0 warning, +0 streak.
- При `warnCount >= 3` в окне → **сброс `currentStreak` в 0**, обнулить warnCount, показать эмпатичный экран ассистента.
- **Freeze:** 1 раз в **14 дней** пользователь может нажать «спасти огонёк» при **одном** предстоящем warning (не при полном красном игноре неделю).

Опять же, числа **3 предупреждения / 7 дней** — в конфиг.

## 12. Фазы разработки (дорожная карта)

### Фаза A — Прототип (2–3 недели человеко-недели)
- Навигация, пустые экраны, мок-данные.
- Модель локальной БД v0 + CRUD рутины и одной недели целей.
- Экран «Сегодня» с отметками без XP.
- Каркас **аутентификации** (экран входа / регистрации) и заготовка под облако (без полной синхронизации всех сущностей можно дозакрыть в B).

### Фаза B — MVP логика (3–5 недель)
- **Auth + облако:** регистрация/вход, привязка данных пользователя к аккаунту, восстановление на чистой установке.
- Закрытие дня, расчёт green/yellow/red, начисление XP.
- Огонёк + предупреждения по конфигу.
- Недельный отчёт (авто-текст + ручные поля).
- Магазин: 10–15 предметов, превью ассистента.
- Онбординг.
- **Локализация: EN (базовые строки)**; подготовка к **uk** (вынести все строки в ARB, второй `app_uk.arb` можно заполнить в фазе C).
- **Локальные уведомления в шторке:** напоминание закрыть день, опционально утренний обзор (настраиваемое время, каналы Android).

### Фаза C — Полировка (2–3 недели)
- Анимации огонька, haptics.
- Баланс экономики по внутренним тестам.
- Тёмная тема, доступность (размер шрифта).
- **Украинский UI (uk):** полный перевод или основные экраны + постепенное добивание.
- Подготовка к стору: иконка, скриншоты, описание **на EN** (и при желании uk).
